# SEMed Tools

แอปรวมเครื่องมือของ SEMed (Electron, Windows) — ตอนนี้มี "ตรวจไฟล์ผลตรวจปอด" (Spirometry) และแท็บดาวน์โหลดโปรแกรมอื่น ตรวจไฟล์ในเครื่องเท่านั้น ไม่แก้ไฟล์ ไม่ส่งข้อมูลออกอินเทอร์เน็ต

## คำสั่งที่ใช้บ่อย
| คำสั่ง | ทำอะไร |
|---|---|
| `npm install` | ติดตั้งไลบรารี (ครั้งแรก) |
| `npm start` | รันแอปเพื่อทดสอบ |
| `npm test` | เทสต์ตรรกะตรวจ |
| `npm run dist` | build ตัวติดตั้ง `.exe` ลงโฟลเดอร์ `dist/` (ไม่อัปโหลด) |
| `npm run release` | build แล้วอัปโหลดขึ้น GitHub Releases (สคริปต์ `scripts/release.js` ทำทีละไฟล์ กัน Release ซ้ำ) |
| `npm run release:check` | ตรวจ Release ของเวอร์ชันปัจจุบันบน GitHub ว่ามีไฟล์ครบ 3 ไฟล์และ `latest.yml` ตรงเวอร์ชัน (ไม่ต้องมี token) |
| `npm run icon` | สร้าง `build/icon.png` ใหม่จากโลโก้ `src/renderer/icon/Logosemed.png` |

> ถ้าเปิดจาก VS Code แล้วขึ้น `Cannot read properties of undefined (reading 'handle')` ให้ล้างตัวแปร `ELECTRON_RUN_AS_NODE` ก่อน

## โครงสร้าง
- `src/core/validator.js` — ตรรกะตรวจ (pure function: `validateFile(buffer, fileName)`, `validateFiles([...])`)
- `src/main/` — main process, preload (IPC), ตัวอัปเดต
- `src/renderer/` — UI ภาษาไทย (ฟอนต์อยู่ในเครื่อง ใช้ออฟไลน์ได้)
- `test/` — เทสต์ (เทสต์บางข้อใช้ไฟล์จริงจากโฟลเดอร์ `ex/` ซึ่งไม่ได้อยู่ใน git เพราะเป็นข้อมูลคนไข้)

## แท็บ "โปรแกรมอื่น" (ดาวน์โหลดโปรแกรม / เปิดเว็บ)
แท็บ "โปรแกรมอื่น" ดึงตัวติดตั้งล่าสุดจาก GitHub Releases ของ repo ที่กำหนดไว้ แล้วมีปุ่มดาวน์โหลด → เปิดตัวติดตั้ง
ไฟล์ลงที่โฟลเดอร์ Downloads และตรวจ SHA-256 กับค่าที่ GitHub รับรอง (ถ้ามี) โหลดได้เฉพาะไฟล์ Release ของ repo ที่ระบุใน `src/main/tools-core.js` เท่านั้น
- **เพิ่ม/แก้เครื่องมือ**: แก้รายการ `TOOLS` ใน `src/main/tools-core.js`
  - `type: 'github'` + `repo: 'owner/repo'` — repo ต้องเป็น public และมี Release ที่แนบไฟล์ `.exe`
  - `type: 'web'` + `url: 'https://...'` — ปุ่มเปิดเว็บในเบราว์เซอร์
- ผลจาก GitHub ถูกจำไว้ 10 นาที (ไม่ล็อกอินเรียกได้ 60 ครั้ง/ชม.) กด "โหลดรายการใหม่" เพื่อบังคับโหลดใหม่
- repo private ใช้ไม่ได้ เพราะแอปไม่มี token — ให้อัปโหลดตัวติดตั้งเป็น Release ใน repo public แทน

## เวอร์ชัน (Semantic Versioning: `MAJOR.MINOR.PATCH`)
เลขเวอร์ชันอยู่ที่ `version` ใน `package.json` แสดงที่มุมขวาบนของแอป (เช่น `v1.0.1`)

| เปลี่ยนอะไร | ใช้คำสั่ง | ตัวอย่าง |
|---|---|---|
| **Patch** — แก้บั๊ก / ปรับข้อความ / ปรับ UI เล็กน้อย | `npm version patch` | 1.0.0 → 1.0.1 |
| **Minor** — เพิ่มความสามารถใหม่ (ไม่กระทบของเดิม) | `npm version minor` | 1.0.1 → 1.1.0 |
| **Major** — เปลี่ยนกติกาตรวจ/พฤติกรรมครั้งใหญ่ | `npm version major` | 1.1.0 → 2.0.0 |

`npm version` จะแก้ `package.json`, สร้าง commit และ tag `vX.Y.Z` ให้อัตโนมัติ
ตัวอัปเดตจะอัปเดตก็ต่อเมื่อเลขเวอร์ชันบน GitHub **สูงกว่า** เวอร์ชันที่ติดตั้งอยู่ ถ้าลืมเพิ่มเลขเวอร์ชัน เครื่องผู้ใช้จะไม่เห็นอัปเดต

## ระบบอัปเดตออนไลน์ (ไม่ต้องไปติดตั้งใหม่ทุกเครื่อง)
แอปใช้ `electron-updater` ดึงอัปเดตจาก GitHub Releases ของ repo `Mamypopo/semed-exe`
ติดตั้งตัวแรกครั้งเดียว หลังจากนั้นทุกครั้งที่เปิดแอป (ต้องมีเน็ต) แอปจะเช็กเวอร์ชันใหม่ให้
ถ้ามี จะขึ้นแถบด้านบน **"มีเวอร์ชันใหม่ X" [อัปเดตเลย] [ไว้ทีหลัง]** — ผู้ใช้เลือกเอง แอปไม่โหลดหรือติดตั้งอะไรเองโดยไม่ถาม
กด "อัปเดตเลย" → ดาวน์โหลด → กด "ติดตั้งและรีสตาร์ท" ส่วน "ไว้ทีหลัง" แถบจะหายไปจนกว่าจะเปิดแอปครั้งถัดไป หรือกดลิงก์ **"ตรวจสอบอัปเดต"** มุมขวาบนได้ทุกเมื่อ
ถ้าออฟไลน์ แอปยังใช้งานได้ตามปกติ และอัปเดตทำงานเฉพาะแอปที่ติดตั้งแล้ว (ไม่ทำงานตอน `npm start`)

### ขั้นตอนปล่อยเวอร์ชันใหม่ (สำหรับผู้ดูแล)
ตั้งค่าครั้งแรก: สร้าง GitHub token (Fine-grained: Contents Read and write, หรือ classic: `repo`) แล้วคัดลอก `.env.example` เป็น `.env` ใส่ `GH_TOKEN=...` (ไฟล์ `.env` ไม่ขึ้น git)

ทุกครั้งที่ปล่อย: commit โค้ดให้เรียบร้อยก่อน (working tree ต้องสะอาด) แล้วรันคำสั่งเดียว

| คำสั่ง | ทำอะไร |
|---|---|
| `npm run ship` | patch (1.0.0 → 1.0.1) |
| `npm run ship:minor` | minor (1.0.1 → 1.1.0) |
| `npm run ship:major` | major (1.1.0 → 2.0.0) |

แต่ละคำสั่งทำตามลำดับ: `npm test` → เพิ่มเลขเวอร์ชัน + tag → `git push --follow-tags` → build และอัปโหลด Release
ถ้าขั้นไหนพัง (เช่นเทสต์ไม่ผ่าน) จะหยุดที่ขั้นนั้น
ขั้นสุดท้ายสคริปต์จะตรวจ Release บน GitHub ให้เอง (ไฟล์ครบ, ไม่ใช่ draft, `latest.yml` ตรงเวอร์ชัน) ถ้าขึ้น ✓ แปลว่าผู้ใช้อัปเดตได้ ถ้าเกิดปัญหากลางทาง รัน `npm run release` ซ้ำได้ (จะใช้ Release เดิมและแทนที่ไฟล์)

เครื่องผู้ใช้ที่ติดตั้งไว้แล้วจะได้เวอร์ชันใหม่ในการเปิดแอปครั้งถัดไป

### ข้อควรรู้
- repo ต้องเป็น **public** แอปที่ติดตั้งจึงดึงอัปเดตได้โดยไม่ต้องมี token (ห้ามใส่ข้อมูลคนไข้ใน repo)
- ตัวติดตั้งยังไม่ได้เซ็นชื่อ (code signing) Windows SmartScreen อาจเตือนตอนติดตั้งครั้งแรก
- ห้ามลบหรือแก้ `latest.yml` ใน Release ด้วยมือ
